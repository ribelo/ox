# OxCaml mode decisions

This pass uses OxCaml 5.4.0+ox and the pinned Eio interfaces. “Global” means the existing unrestricted callback parameter; it does **not** prove domain portability. The table records every public function with a closure argument in current interfaces (nmodes-d2rn, nmodes-8t8v, nmodes-8y46).

| Public function | Callback decision and reason |
| --- | --- |
| `Ox.Result.Syntax.( let* ), ( let+ )` | **Global**; although applied immediately, OxCaml binding-operator elaboration rejects a mode-qualified closure parameter in existing `let*` syntax. |
| `Ox.Retry.retry, repeat` | **Local**; invoke in the calling fiber. Top-level tail-recursive helpers accept the local callback explicitly rather than capture it in an escaping recursive closure. The `policy` record's callbacks (`is_success`, `is_worth_retrying`, `on_retry`) are **global** and run in place: they are fields of a plain record, and a record of local closures would need every caller to annotate it. |
| `Ox_otel.Meter.create ~now_ms ~record` | **Global**; both callbacks are retained: `now_ms` by the meter, `record` for every measurement the instruments ever make. |
| `Ox_otel.create ~on_error ~on_signal_error` | **Global**; both callbacks are retained by the exporter for later failures, including switch release. |

## Typed errors across a fork (nsup-hje5)

A `handled_effect`-style local token — a `local` handler value that the mode system guarantees is handled — cannot cross `Fiber.fork`: Eio's fork closures are **global**, so a closure capturing a local value cannot escape into the new fiber, and a forked fiber would have to install a handler of its own, which is no longer the caller's. There is no way around this inside Eio as pinned, and the search is closed: `Scope.supervised_error` is the chosen answer. A typed `Error` returned by a forked fiber travels **by value**: `fork_error` resolves the fork's promise, records the first error in the scope's cell, and ends the scope with a private exception that `Eio.Switch.fail` uses to cancel and await the other forks; the boundary returns the recorded `Error`. The private exception never appears in an interface, and every other exception and every cancellation passes through untouched.

The one upstream request that would change this: mark the body of `Eio.Switch.run` (and `Fiber.fork`) as safe for local capture — a `local` closure argument whose captured locals may not escape past the switch's lifetime — so that a handler value created outside a switch could be used inside its forks. Until Eio takes it, nobody re-opens the search. A second pinned quirk found by the same work: `Eio.Fiber.pair` documents fail-fast but forks its first side as a promise, so a failure there does not cancel the second side; `Concurrent.par` is built on `Fiber.both` instead.

## Portable functions and values (nmodes-6pqn)

The interfaces of `Duration`, `Schedule`, `Cause`, `Exit`, `Interrupt_id`, `Ox_json`, and `Status` begin with compiler-checked `@@ portable`, making their unexcepted functions portable to call from another domain. This is a property of a **function closure**, not an automatic guarantee for all values returned by it. `Duration.t` is `value mod portable contended`; `Interrupt_id.t`, `Status.state`, `Status.t` and `Ox_json.t` have compiler-checked portable value kinds. The rows and portability claims of the schema combinator library, removed in row 16 (`^nnoschema-ttb5`), went with it: a derived codec is plain OCaml, and `docs/adr/0008-types-are-the-schema.md` records why. `Ox_json.parse`, `to_string`, and `compact` have explicit `@@ nonportable` exceptions because they close over nonportable pinned `Yojson.Safe` functions; JSON constructors/accessors remain portable.

`Schedule.t` is **not** portable as an arbitrary value: `Recur_until`, `Modify_delay`, and `While_output` hold unrestricted user callbacks. Requiring portable callbacks would reject currently valid single-domain closures over mutable state. The same held for the removed schema library's values, which retained unrestricted callbacks. `Cause.t` is not universally portable because `Fail` stores arbitrary `'e`, and `Die` stores an exception/backtrace; `Exit.t` includes the arbitrary success payload and `Cause.t`. Portable `string Cause.t` is accepted at an explicit portable parameter in the compile test. No representation or callback contract was changed to overpromise portability: portable schedules would be a separate consumer-driven `ox_par` decision.

`test/modes/portability.ml` sends a `Schedule.t` and `Cause.t` via `Eio.Domain_manager.run` and explicitly checks the concrete Cause argument's portable mode. This exercises transfer and demonstrates the limit: the pinned domain manager accepts an unrestricted closure, so this test **does not prove** an arbitrary schedule is portable. It would be incorrect to claim the Eio call itself supplies that proof.

## Single-domain boundaries (nmodes-yp1i)

Create `Logger`, `Context`, `Correlator`, `Supervised`, `Listener`, `Child` and `Ox_otel.Meter` instances per domain. Their Eio handles, fiber-local bindings, mutable counters or unsynchronized lifecycle are not portable state. A meter's instruments aggregate into one exporter-owned table with no lock, so two domains recording through one meter would race. A future parallel package must own separate instances inside each worker domain rather than share these values across domains. Portable pure functions do not make an enclosing mutable handle portable. `Child.stop` and `Correlator.close` might eventually warrant `unique`/`once` contracts; this pass makes neither promise.

## Allocation evidence (nmodes-78o3)

`Duration.ms`, `to_ms`, `is_zero`, `subtract`, `min`, `max`, `between`, `compare`, and `equal` pass the native compiler's `[@@zero_alloc]` checker. Checked arithmetic that can raise, floating-point conversion, formatting and `Duration.divide` do not receive unsupported assertions. A compiler trial of `Schedule.step [@@zero_alloc]` **failed**: `step_phase` may allocate, and the function allocates a 24-byte replacement driver and a 24-byte result pair. Thus adding the requested assertion without a behavior/API rewrite would be a false guarantee. It was reverted. `bench/correlator_alloc.ml` runs 10,000 complete request/reply calls on Eio's posix backend; one measured run reported 291.00 minor words/call, 0.03 major words/call, 291.03 total allocated words/call from `Gc.quick_stat` deltas after a warm-up and full major collection. Numbers depend on compiler, backend and GC settings; benchmark prints the measured count rather than checking a brittle threshold.

## Pinned upstream gaps (nmodes-cikk)

In pinned `eio/core/eio__core.mli`, `Switch.run : ?name:string -> (t -> 'a) -> 'a` and `Fiber.with_binding : 'a key -> 'a -> (unit -> 'b) -> 'b` take unmoded closures. In `eio/time.mli`, `Time.with_timeout : _ clock -> float -> (unit -> ('a, 'e) result) -> ...` also takes an unmoded closure. Trials making `Scope.run`, `Context.with_fields`, or `Timeout.timeout` local failed against those pinned signatures. `Eio.Fiber.fork`, `pair`, and `first` take unmoded/global task callbacks by design (they are scheduled asynchronously). In `eio/domain_manager.mli`, `Domain_manager.run : _ t -> (unit -> 'a) -> 'a` explicitly warns that thread safety is **not enforced by the type**; it does not demand a portable closure. `Stdlib.List.map` similarly prevents passing a local callback in `Ox_json.array_map` without substituting an algorithm. These are version-specific type gaps, not evidence of a safe cross-domain callback.

The ppx pipeline is a tooling gap of the same kind (nppx-d10y). No ppxlib installs on 5.4.0+ox, so dune `(pps ...)` has no driver to run: `ppx-yojson-minimal` preprocesses text through `(preprocess (action ...))` instead. Two consequences follow. First, merlin and ocamllsp do not run the preprocessor, so a derived `t_of_yojson` reads as unbound in the editor while the dune build (which does run it) is green; the build is the source of truth until a real ppxlib exists. Second, the emitted converters are plain OCaml with no mode annotations; a file that derives over a `local` closure or ships values across domains gets no help from the deriver, and a future signature that needs either states it by hand.

## Rules for future signatures (nmodes-o66p)

1. A callback run in place, in the current fiber, and not retained is `@ local`; test it against every callee.
2. A callback forwarded to Eio or stored for later is global, and the interface says why. Global does not imply portable.
3. Pure modules expose portable functions and portable **value kinds only when their contents permit it**. Stored arbitrary callbacks and payloads prevent unconditional portable values; test the mode with the compiler rather than claiming it by analogy.
