# Actor: a typed mailbox with a state fold, supervised in a scope

## Problem Statement

Several long-lived parts of the applications are one mutable state touched by many fibers: Leash's tab registry, Pie's recording coordinator, nema's watcher. Today each guards its state with a `Mutex` and hand-written message handling. Ox's `Actor.create(obj)` gives a typed mailbox over an object; Elixir's GenServer (and Tim Smart's `effect-genserver`) gives `state -> message -> (state, reply)` with the state as an explicit value and a stream of state changes. Eta wants the discipline of the second inside the scope rules of the first, without GenServer's schema, RPC or cluster machinery.

## Solution

`Actor.create ~sw ~init ~handle`: one fiber owns the state; `handle : 'state -> 'msg -> ('state * 'reply, 'e) result` is the whole behaviour; `ask actor msg` sends and awaits the reply, `tell actor msg` sends and returns; messages are processed in order, one at a time; a handler's `Error e` is reported to the asker and leaves the state unchanged; a handler's exception ends the actor and its scope (supervised); `changes actor` is a stream of states for observers; the actor lives exactly as long as its switch.

The same row adds two opt-in modules from Riot std: `Supervisor` owns restartable child scopes under the caller's switch; `Agent` owns state when a caller needs serialized functions rather than an application message protocol. Neither changes the existing `Actor` contract, and neither introduces a process runtime. Both build on [typed supervised forks](</home/ribelo/projects/ribelo/ocaml/ox/docs/issues/supervised-error/01-supervised-error.md>) and [ADR-0009](</home/ribelo/projects/ribelo/ocaml/ox/docs/adr/0009-ox-is-the-floor.md>).

## User Stories

1. As a service author, I want `Actor.create ~sw ~init ~handle` returning `('msg, 'reply, 'e) Actor.t`, where `handle : 'state -> 'msg -> ('state * 'reply, 'e) result`, so that a stateful component is one pure fold plus a mailbox. ^nactor-agcr
2. As a service author, I want `Actor.ask actor msg : ('reply, 'e) result` to enqueue and await, and `Actor.tell actor msg : unit` to enqueue and return, so that both request-reply and fire-and-forget are available. ^nactor-jhl2
3. As a service author, I want messages handled strictly in arrival order, one at a time, so that the state needs no lock. ^nactor-mb6v
4. As a service author, I want a handler returning `Error e` to answer that `ask` with `Error e` and leave the state as it was, so that typed failures do not corrupt state or stop the actor. ^nactor-7qi7
5. As a service author, I want a handler raising an exception to end the actor and fail its switch with that exception (Ox supervision), with every pending `ask` answered `Error \`Actor_stopped`, so that a bug in the actor is loud and structured. ^nactor-pxfz
6. As a service author, I want `Actor.changes actor` to be a bounded stream of states after each successful handler, with documented overflow (drop oldest, count), so that observers (status, UI) can follow without asking. ^nactor-6z3i
7. As a service author, I want `Actor.state actor` to return the current state without sending a message (a snapshot read), so that cheap reads do not queue behind writes. ^nactor-l87k
8. As a service author, I want the mailbox bounded (default 1024) with `tell` blocking when full and `try_tell` returning `false`, so that a slow actor applies backpressure instead of growing without limit. ^nactor-512k
9. As a service author, I want `ask` to accept an optional `?timeout` and to answer `Error \`Timeout` without disturbing the actor, so that a caller can bound its wait. ^nactor-tc19
10. As a service author, I want the actor to stop when its switch ends: the mailbox is closed, in-flight handling finishes, pending asks get `\`Actor_stopped`, and `changes` ends, so that the actor is a resource like any other. ^nactor-e0l5
11. As a service author, I want an optional `~on_stop : 'state -> unit` run once at the end with the final state, so that state can be persisted or reported at shutdown (GenServer's `terminate`), without Eta owning persistence. ^nactor-oxao
12. As a maintainer, I want one consumer moved onto `Actor` in the same row — Leash's tab registry is the candidate — with its 108-cell authorization tests unchanged, so that the abstraction is proven on real state. ^nactor-8z1n

13. As a service author, I want an OTP-style `Supervisor` under an explicit Eio switch, with each child a supervised fork, `OneForOne` / `OneForAll` / `RestForOne` / `SimpleOneForOne` strategies, `Permanent` / `Temporary` / `Transient` restart types, `BrutalKill` / `Timeout` / `Infinity` shutdown, restart intensity `{ max_restarts; window }` ending the supervisor with a typed error carrying the last child Cause, and significant children with `auto_shutdown`, so that a recoverable service group can restart in dependency order without escaping its owning scope. ^nactor-d120
14. As a service author, I want `Agent.create ~sw ~init` returning a state-parameterized handle with `get`, `update`, `get_and_update` and `cast`, all executed by one owner fiber without defining a message type, so that a shared counter, cache or small state holder has serialized access without an Actor protocol. ^nactor-75ef

## Implementation Decisions

- One `Eio.Stream` for the mailbox, one fiber forked on `sw` looping `take` → `handle` → resolve the ask's `Promise`; `changes` is a second bounded `Eio.Stream`.
- `ask` = a `Promise` per message; `tell` = no promise. The actor's fiber is a plain `Fiber.fork`; an exception escapes to the switch, which is Ox's supervision.
- No schema, no RPC binding, no persistence, no cluster: GenServer's protocol typing is OCaml's variant type for `'msg`.
- The state type is the author's; immutability is the discipline, not enforced.

### Story 13 — Supervisor (nactor-d120)

- An opt-in restart boundary, not a new cancellation system: the caller supplies `~sw` and a clock. An ordered child specification has a stable id, a fresh-start function, restart type, shutdown mode and significance. Each incarnation gets its own nested `Scope.supervised_error` and `Scope.fork_error`; resources are acquired on that child's switch. A child completion is published to the supervisor only after its scope has released resources. Never put raw restartable `Error e` forks directly in one shared fail-fast scope: that would cancel unrelated children before the strategy could decide. The supervisor itself is a supervised fork whose terminal typed error ends its owning supervised scope.
- The Supervisor is a classification boundary like `Scope.run` ([ADR-0009](</home/ribelo/projects/ribelo/ocaml/ox/docs/adr/0009-ox-is-the-floor.md>)): a child's typed `Error e` becomes `Cause.Fail e`; a non-cancellation exception becomes `Cause.Die (exn, backtrace)`, is logged with its backtrace, and is eligible for restart. Cleanup failures remain in the full child Cause, not discarded in favour of the body result. Cancellation is never caught as a defect or converted into a typed failure: external cancellation propagates with its identity, cancels and awaits all children, and never triggers recovery. Supervisor-requested stop/restart is marked as such before cancellation; its resulting interruption is not a fresh failure event. A cleanup defect during requested shutdown is still reported in the supervisor's terminal Cause, never discarded as an expected interruption. This explicit boundary does not change ordinary combinators' rule that exceptions propagate unchanged. An Actor defect still fails its immediate child switch as story 5 requires; only an explicitly enclosing Supervisor classifies that completed scope and decides whether to restart it.
- A single supervisor fiber serializes completion and control events. Child id plus incarnation number replaces a pid/monitor reference: ignore stale completion from an earlier incarnation, and never run two incarnations of one child concurrently. Startup and restart follow specification order; group shutdown follows reverse order. Start functions create fresh state and resources, not reuse a stopped Actor/Agent handle. They must expose their complete child lifetime, not return immediately after spawning work elsewhere. Startup readiness and publishing replacement handles are explicit API questions below.
- Restart eligibility is tested on the child that exited: `Permanent` restarts on normal `Ok ()`, typed failure or defect; `Temporary` never restarts; `Transient` restarts on typed failure or defect, but not normal completion. An ineligible exit does not restart siblings. Explicit supervisor shutdown overrides all restart types. Abnormal means the completed scope's Cause, including cleanup failure, not cancellation of the owning scope.
- `OneForOne` restarts only the eligible child. `OneForAll` stops the remaining active group, awaits cleanup, then restarts the failed child and its restartable active siblings. `RestForOne` does the same for the failed child and active children later in specification order; earlier children are untouched. Collateral `Temporary` children are stopped and removed, never restarted; collateral `Transient` children are restarted as part of the group even though their stop was requested. A previously normally completed Transient is not revived by a later group restart. Induced stops do not recursively initiate another strategy or count as new spontaneous exits.
- `SimpleOneForOne` accepts exactly one template and starts zero initial instances. `start_child` supplies instance input to that template and returns a fresh instance handle; automatic restarts reuse that instance input and replace only that instance. Explicit termination removes the instance and does not restart it. This is a real dynamic-template strategy, not Riot's current alias to `OneForOne`; no separate general-purpose Dynamic module or registry is pulled in.
- Shutdown is cooperative. Each child has an idempotent stop-request signal (an Eio promise or equivalent, passed to its start function). `Infinity` requests graceful stop and awaits completion with no local deadline. `Timeout duration` requests stop, waits using `timeout` and the supplied clock, then cancels the child's Eio cancellation context if the grace period expires; it still awaits resource release before returning or restarting. `BrutalKill` skips the grace signal and requests cancellation immediately, but still runs finalizers and joins. Eio cannot forcibly kill a fiber, skip its finalizers or impose a hard upper bound on cancellation-protected cleanup; a non-yielding fiber also prevents the deadline from running. These names do not promise BEAM-style killing. Parent cancellation takes precedence over graceful modes, including Infinity. No detached cleanup, second cancellation model or race-against-sleep timeout.
- Intensity uses a supplied monotonic clock and a rolling window: discard timestamps at or before `now - window`; allow at most `max_restarts` recovery attempts in `(now - window, now]`. One strategy batch counts as one attempt, not one per collateral child; a failed restarted incarnation that needs another recovery consumes another attempt. Initial starts and explicit stops do not consume the budget. Before the attempt that would exceed it, stop and await every child and return `` Error (`Restart_intensity_exceeded { child_id; max_restarts; window; last_cause }) ``, retaining the full last child Cause (including a defect's backtrace); `last_cause` is optional only because a Permanent child can also exhaust the budget by repeatedly completing normally. Every abnormal exit is logged, including one not eligible for restart. A successful restart never erases a defect's logged diagnostic. Validate nonnegative max_restarts (zero disables automatic restart), positive window, unique ids and nonnegative shutdown durations before starting any child. No unbounded restart loop hidden inside a start function.
- `auto_shutdown = Never | AnySignificant | AllSignificant` defaults to Never. Only Temporary and Transient children can be significant; reject significant Permanent children, and reject significance for the dynamic-template strategy in this row. A significant Temporary's spontaneous exit of either kind, or a significant Transient's normal exit, is terminal and counts toward automatic shutdown; a Transient failure that will restart does not. AnySignificant stops the supervisor at the first such exit; AllSignificant waits for all configured significant children to finish (an empty set does not auto-stop). Strategy-induced stops and explicit child removal do not count as significant completion. Automatic shutdown stops and awaits remaining children and yields normal completion; it does not erase the failed child's logged Cause. Restart-intensity failure remains a typed failure, never normal auto-shutdown. This is an explicit OTP-style extension beyond Riot's unconditional significant-child failure.

### Story 14 — Agent (nactor-75ef)

- `'state Agent.t` has no public message parameter or user-defined handler. `init : unit -> 'state` runs once in the owner fiber. `get agent ~fn` applies `fn : 'state -> 'reply`; `update` applies `'state -> 'state` and acknowledges only after replacement; `get_and_update` applies `'state -> 'reply * 'state`, commits the new state and replies atomically with respect to other requests; `cast` enqueues `'state -> 'state` without waiting for execution. The tuple order is Riot's (reply, state), not Actor's (state, reply).
- All four functions queue on a bounded mailbox (default 1024) in acceptance order, even get; there is no bypass snapshot like `Actor.state`. One owner runs every closure, including reads, one at a time. A private GADT/existential request carries each reply's typed Eio promise; callers need no message type, type witness, `Obj.magic`, process mailbox or pid. Cast can block on a full mailbox: fire-and-forget means no execution acknowledgement, not unlimited buffering.
- The operations return `result` with `` `Agent_stopped `` for a closed owner (get/get_and_update return the reply, update/cast unit on success). Cast's success means accepted only. This adds Ox's typed lifecycle error to Riot's plain-return API; it does not introduce a typed failure protocol for callbacks. Callback exceptions fail the owning switch unchanged, including those from cast, and are only restartable if the caller deliberately puts that scope under Supervisor. Every pending reply and blocked admission is released on owner termination; external caller cancellation stays cancellation, not Agent_stopped. Switch closure ends the owner and leaves no queued operation or reply waiting forever.
- Cancellation of a caller after admission does not roll back or promise to retract the accepted operation. Commit precedes a synchronous acknowledgement; a cancelled waiter need not receive it. Closures must not synchronously call back into their own Agent (deadlock), and should not block for long. State immutability and not leaking mutable aliases through replies remain the author's discipline; serialization is not memory isolation or transactional rollback. No changes stream, named process, links, monitors or detached start; Actor remains the choice for a domain message protocol.

### Riot → Eio / Ox mapping

| Riot std concept | Eio / Ox realization and deliberate difference |
| --- | --- |
| Supervisor process, start/start_link, pid | Explicit parent switch; supervised owner fiber and typed handle. No detached start, process links or bidirectional link propagation. |
| Child spec start, Worker/Supervisor | Fresh-start function runs the full child lifetime on a nested supervised switch; a nested supervisor is an ordinary scoped child, not a runtime process category. |
| monitor / DOWN / demonitor | Join/completion result plus child id and incarnation, delivered to the single owner; scope ownership propagates cancellation and release replaces unlinking. Eio has no process links or monitors. |
| OneForOne / OneForAll / RestForOne | Isolated child scopes and ordered restart batches; stop and join before replacement. Eligibility is checked before touching siblings. |
| SimpleOneForOne | One reusable template with dynamic instances and retained restart input; complete the advertised behavior rather than copy Riot's alias. |
| Permanent / Temporary / Transient | Normal Exit versus typed Cause or classified defect; policy as above, never restart parent cancellation. Ordinary combinators still re-raise defects unchanged. |
| BrutalKill / Timeout / Infinity | Immediate Eio cancellation / grace signal plus deadline then cancellation / grace signal and unbounded local wait; all join and run finalizers, never force-kill a fiber. |
| intensity { max_restarts; window } | Monotonic rolling-window budget; check before a recovery batch, count attempts (including failed attempts), typed terminal error retaining last Cause. Riot currently counts successful child restarts individually and checks afterwards. |
| significant / auto_shutdown | Validated significant children and explicit Never/AnySignificant/AllSignificant policy. Riot exposes significant but has no auto_shutdown selector at the inspected revision. |
| Agent state + get/update/get_and_update/cast | One state-owning fiber, closure requests and typed promises; no public message type, bounded admission and typed Agent_stopped. |
| Agent spawn / spawn_link and receive reply | Switch-owned fiber only; per-request promise correlates replies of different types, not a shared process response mailbox. |

## Testing Decisions

- Seam: public module under `Eio_main` with `Eio_mock.Clock` (`test/core`). Ordering under concurrent tells; error leaves state; exception fails the switch and answers pending asks; changes stream and overflow; backpressure; timeout; stop on switch end; `on_stop` once.
- Story 12: Leash's existing registry tests.

- Story 13 (nactor-d120): public Supervisor under `Eio_main` with mock time and scripted children, not process emulation. Table-test all four strategies against all three restart types and normal completion / typed failure / defect, with mixed-policy siblings. Record starts, stop requests and finalizer completion: reverse stop order, forward restart order, no affected incarnation overlaps, no unaffected sibling cancellation and no restart for external cancellation. A defect is logged with its original exception/backtrace and remains in the intensity error's last Cause; ordinary `Scope.supervised_error` and Actor without Supervisor still propagate it unchanged. Include finalizer defects and external cancellation identity.
- Story 13 (nactor-d120): advance mock time across exactly `window`, `max_restarts = 0`, exactly the allowed budget and the next attempt. Verify batch-versus-child counting, failed restart attempts, no extra start after exhaustion, and that the typed error is returned only after child cleanup. Validate invalid configuration before any child starts. For shutdown, assert grace signal/early completion/deadline cancellation/Infinity/BrutalKill, plus parent cancellation during each mode. A gated cancellation-protected finalizer proves the timeout does not falsely claim a hard kill; release the gate so the test itself terminates. Test stale completion, simultaneous exits and dynamic-template instance isolation with deterministic barriers rather than sleeps.
- Story 13 (nactor-d120): cover Never/AnySignificant/AllSignificant with Temporary exits, normal Transient completion, restarting Transient failure, no significant children, invalid Permanent significance, and group-induced stops. Verify all remaining children are awaited, a terminal child's diagnostics survive normal auto-shutdown, and intensity exhaustion remains an error. Nest one Supervisor to prove ownership and propagation without links or monitors.
- Story 14 (nactor-75ef): public Agent tests with concurrent increments and atomic get_and_update returning each previous value exactly once; mixed get reply types on one state handle; read-after-update and read-after-cast barriers; init once in the owner; no overlapping callbacks even when one yields. Capacity-one tests show cast backpressure and acknowledgement after admission versus update acknowledgement after commit. Compile a consumer using all four operations without any message declaration.
- Story 14 (nactor-75ef): cancel a caller before and after admission, close the owner with pending replies and a full mailbox, and assert every waiter/blocked producer is released with the specified lifecycle result or original caller cancellation. Raise in init and in each callback (including cast), assert the same defect fails the owning switch and no fiber leaks; repeat with an explicitly supervised child to prove a fresh Agent is created, not a stopped handle revived. No wall-clock sleeps or testing a hung self-call as normal operation.

## Out of Scope

Persistence, distribution, named registries, supervision outside the owning switch, hot code reload. Story 13 permits nested supervisor child switches within that ownership only; no detached process tree, process-link emulation or general Dynamic supervisor API. Story 14 does not add a message protocol or Agent changes stream.

## Further Notes

Tim Smart's effect-genserver was read for its handler shape (`state -> payload -> (state, reply)`, `changes` stream, `toLayerPersisted`); its Layer/Context wiring, RPC schemas and cluster entities do not fit and are not taken. Ox's `Actor.create(obj).ask(_.method)` wraps a mutable object with no supervision beyond the scope and no state stream; Eta takes its scope discipline and the explicit-state fold instead of the object.

Riot reference: [Supervisor interface](<https://github.com/leostera/riot/blob/2ec367e7a3024ac9ebc2958debb0b7369c3d093f/packages/std/src/supervisor.mli>), [Supervisor implementation](<https://github.com/leostera/riot/blob/2ec367e7a3024ac9ebc2958debb0b7369c3d093f/packages/std/src/supervisor.ml>), [Agent interface](<https://github.com/leostera/riot/blob/2ec367e7a3024ac9ebc2958debb0b7369c3d093f/packages/std/src/agent.mli>) and [Agent implementation](<https://github.com/leostera/riot/blob/2ec367e7a3024ac9ebc2958debb0b7369c3d093f/packages/std/src/agent.ml>), inspected at revision `2ec367e7a3024ac9ebc2958debb0b7369c3d093f`. This is a semantic reference, not a dependency or code transplant. Its static Supervisor currently sends EXIT for shutdown with TODOs instead of enforcing Timeout/Infinity, dispatches SimpleOneForOne to OneForOne, uses spawn for both start and start_link, and turns any significant-child exit into a Failure. No auto_shutdown selector exists in the inspected std. The mapping above specifies the desired behavior explicitly rather than treating those gaps as guarantees.

### Open design questions for the lead

- Which first consumer proves each new module in row 47? The existing story 12 Actor migration remains unchanged; it alone does not demonstrate restart policy or Agent ownership.
- Finalize Supervisor construction/run/await signatures and the child start readiness handshake: how does a dependent child obtain the new typed Actor/Agent handle on restart without adding a named registry? The lifetime and cancellation contract above must not depend on a fire-and-forget start function.
- Confirm the specified recovery-batch intensity accounting and half-open window, rather than Riot's per-successful-child count and inclusive cutoff. These are deliberate, testable choices; changing them changes the tests, not just names.
- Confirm Never/AnySignificant/AllSignificant as this row's auto_shutdown surface (Riot only has the significant flag), including the static-only significance restriction and whether explicit removal should affect AllSignificant membership.
- Does a consumer require result-returning Agent update callbacks or per-request timeouts in this row? The current contract takes Riot's plain closures and adds only typed lifecycle failure; do not silently grow it into a second Actor protocol.
