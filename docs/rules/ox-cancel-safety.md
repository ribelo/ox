# ox-cancel-safety

A typed, selected interface value must explicitly classify cancellation safety as “safe to re-run”, “unsafe because data is lost” or “unsafe because progress is lost”. Follow the [interface documentation contract](interface-documentation.md) for period-terminated shapes, exemptions and module-default precedence. ^nlintd-vneh ^nlintd-z5p5 ^nlintd-4ja0 ^nlintd-6abn

Never-suspending, non-cancellation-point operations and operations protected throughout are exempt. Partial protection is not a whole-operation exemption. Overriding a default's suspension/cancellation resets its inherited safety claim. The rule also checks implementation-backed cleanup obligations for “safe to re-run”, “cancel-safe” and “no resource left” claims. For recognised typed channel acquisitions (and switch-owned Eio path/network acquisitions), the same resource must have a guaranteed close before cancellation escapes, a previously registered switch hook, or a guaranteed `Fun.protect ~finally` close. A success-only close, late hook, conditional hook, hook that ignores the resource, or finalizer that can be cancelled before closing is not a witness. Switch release callbacks are cancellation-protected; opaque cleanup helpers produce named undecided rather than guessed proof. ^nlintd-cleanup

This finite resource-path check does not establish idempotence, data-loss semantics or arbitrary retry safety. Missing/stale evidence and unsupported callback/functor paths remain named undecided, fatal under `--require-typed`; explicit dependency qualifications describe limits, not proof of cleanup.
