# Types are the schema: derived codecs, no schema DSL

Wire and config shapes are ordinary OCaml types with derived JSON codecs (`[@@deriving yojson]` through a Jane Street or community deriver built for OxCaml). Values with constraints the type cannot express are their own modules with an abstract type and a smart constructor (`Port.of_int : int -> (t, _) result`) and their own codec, so the record says `port : Port.t` and the constraint lives with the type: parse, don't validate. There is no schema combinator library: `eta_schema` and `eta_schema_yojson` are removed.

Effect Schema exists because TypeScript's types are erased and it has no macro system; a schema value is TypeScript's deriving. OCaml has ppx, so the type is the single source and the deriver produces the codec. What a value-level schema still offers was weighed and answered without a DSL: located decode errors come from the deriver (the offending subtree or a dotted path — a small loss, improvable in a custom deriver); field metadata is types (`Redact.t` redacts by being what it is) and explicit functions (environment overrides); JSON Schema for LLM tool definitions and structured outputs — the one strong use, and what v1's `eta_ai` used `eta_schema` for — is a second deriver on the same type (`[@@deriving jsonschema]`) when the AI package is pulled, and until then a hand-written page per tool; runtime-defined shapes have no consumer and would be a local value if one appeared. The toolchain constraint (no published OxCaml ppx stack for 5.4) is a task, not a reason: row `ppx-on-oxcaml` makes deriving work from the OxCaml monorepo sources.
