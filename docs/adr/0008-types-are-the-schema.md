# Types are the schema: derived codecs, no schema DSL

Wire and config shapes are ordinary OCaml types with derived JSON codecs (`[@@deriving yojson]` through a Jane Street or community deriver built for OxCaml), plus hand-written validation where a value has constraints the type cannot express. There is no schema combinator library: `eta_schema` and `eta_schema_yojson` are removed. A schema DSL restates the type system in values, doubles every shape, and reads badly; what it offered beyond deriving — located decode errors, field marks, JSON Schema generation — is obtained from the deriver's error (which carries the offending subtree), from types (`Redact.t` redacts by being what it is; environment overrides are a function), and, when an AI tool definition needs JSON Schema, from a deriver for that purpose at that time. The toolchain constraint (no published OxCaml ppx stack for 5.4) is a task, not a reason: row `ppx-on-oxcaml` makes deriving work from the OxCaml monorepo sources.
