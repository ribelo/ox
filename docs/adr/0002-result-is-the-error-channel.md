# `('a, 'err) result` is the error channel; Cause is computed at scope boundaries

Typed failures are the `Error` side of `result`, named by polymorphic variants so unions compose by inference. Exceptions are defects. `Scope.run` catches at a scope boundary and classifies into the Cause tree (typed failure, defect, interruption with identity, finalizer failure, compositions), which is the one v1 idea kept whole.

The serious alternative — typed failures as effect operations that require a `local` handler token, the pattern of Jane Street's `handled_effect`, which makes "unhandled" a compile error — was tested on 2026-09-26 with a 25-line reimplementation on OxCaml 5.4.0+ox and Eio 1.3+ox (`.scratch/research/handled-pattern/README.md`, reproducible with `run-all.sh`). Findings: the token does prevent escape and unions infer cleanly with one token; an installed handler survives suspension, cancellation and cleanup inside one fiber; but Eio's `Switch.run`, `Fiber.fork`, both `Fiber.pair` branches and `Fiber.first` take global closures, so the compiler rejects carrying the token into any of them — correctly, since the raw-effect control hits `Effect.Unhandled` in a forked fiber — which means every switch and fiber must reinstall its own handler and hand the outcome back as a `result` anyway; and perform-and-catch measured 50× slower than `Error`/`match` (504 vs 16 bytes allocated per failure). A kernel whose every scope is a Switch gains nothing from it and pays plumbing and cost. Decision: `result` everywhere; local-token handlers are permitted only as a private fail-fast helper *inside* one fiber, never across a scope boundary, and never in a public signature. The v1 R-channel research on 5.2.0+ox reached the same fiber-boundary finding for service effects.
